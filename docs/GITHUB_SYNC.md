# 源码同步与发布交接

本仓库 `anbeby/guazi` 的 `main` 保存已整理的源码。2026-10-15 只读核对业务服务器 `192.168.3.5`：API 的 74 个 Python 文件及 Odoo 插件的 68 个源码/配置文件与本仓库一致；本地现成前端构建目录与运行容器存在差异，不能据此认定前端源码对应当前线上构建。实际发布前须重新构建并核对前端产物。

## 每次代码更新

1. 在开发副本修改、测试并提交到 GitHub；检查提交中没有 `.env`、密钥、数据库、备份、用户上传文件或生成目录。生产热修须回收到源码仓库，不让线上独自成为唯一版本。
2. 为通过验收的提交打唯一版本标签，记录提交 SHA、API/前端镜像 ID 和发布包 SHA256。前端从该提交重新构建，验证页面与接口；数据库迁移先在独立测试库演练。
3. 用指定提交构建发布镜像和版本包，经现有 SSH 通道交付业务服务器。按照 `docs/瓜子平台后续升级标准流程.md` 建发布计划，先运行 `release-guazi.py check`，通过后再用该文档的 `apply --execute` 正式发布。
4. 发布后记录计划、备份检查点、镜像 ID、数据库修订、健康检查和 GitHub 提交 SHA。回滚按现有发布脚本及迁移边界执行。

## 当前网络与权限

2026-10-15 只读检测：业务服务器到 GitHub 的 HTTPS 和 SSH 不通；阿里云网关到 GitHub 可达。业务服务器当前不适合直接 `git pull`。在受控构建机按固定标签取得源码、验证 SHA256，再通过 SSH 交付镜像包即可；不改动网关现有入口、隧道、证书和配置。将来若业务服务器恢复 GitHub 出口，才考虑为本仓库配置独立只读部署密钥，并在独立版本目录拉取和校验。

仓库目前对外公开；改为私有后仍可按上述方式交付。生产环境不需要 GitHub 写权限，也不应自动推送代码。当前没有启用自动发布。
