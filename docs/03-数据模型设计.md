# 数据模型设计（第一阶段）

数据库：PostgreSQL 16
- `gz_odoo`：Odoo 业务库（由 Odoo 自身管理）
- `gz_platform`：自研平台库，业务表位于 schema `gz`
- 测试环境：可用 SQLite 内存库运行（模型仅使用可移植类型，不使用 JSONB/ARRAY 等 PG 专有类型；PG 侧由 Alembic 建 schema 与索引）

命名规范：表名小写下划线单数；主键 `id`；外键 `xxx_id`；时间 `created_at/updated_at`；金额 `numeric(18,2)`；数量 `numeric(18,3)`（吨/千克三位小数）。

### role / permission / user_role / role_permission
- `role(id, code UK, name, description, is_system, created_at)`
- `permission(id, code UK, name, module, description)`
- `user_role(user_id, role_id)` 联合 PK
- `role_permission(role_id, permission_id)` 联合 PK

内置角色：`platform_admin`（平台管理员）、`park_operator`（园区运营人员）、`merchant`（商户）、`supplier`（供应商）、`buyer`（采购商）、`finance`（财务）。

### 交易状态机（订单）

```
draft ──提交──▶ pending_confirm ──供方确认──▶ confirmed ──发货──▶ delivering
                     │                              │                  │
                     └──取消──▶ cancelled           │                  ▼
                                          (库存扣减+流水)         completed
                                                                     │
                                                              结算 ──▶ settled
```

- `confirmed` 时：按 `order_item` 扣减库存（`quantity` 减、`locked_quantity` 释放）、写 `stock_move(out)`、生成 `transaction_flow`（待收款）。
- `completed` 时：生成/归集 `settlement`（应收）。
- 全部状态变更写 `operation_log`，并通过 `sync_outbox` 推送 Odoo。

## 5. 结算域

- `settlement(id, settlement_no UK, enterprise_id, settle_type[receivable/payable/park_fee], period_start, period_end, order_amount, fee_amount, settle_amount, settled_amount, pay_status[unpaid/partial/paid], receive_status[unconfirmed/confirmed], status[pending/confirmed/settled/cancelled], remark, created_at, confirmed_at)`
- `settlement_line(id, settlement_id FK, order_id nullable, biz_type[order/park_fee/service_fee], biz_no, amount, fee_rate, remark)`
- `transaction_flow(id, flow_no UK, order_id, settlement_id, enterprise_id, counterparty_enterprise_id, direction[in/out], biz_type[order_payment/service_fee/refund/deposit], amount, pay_method[bank_transfer/offline/other], pay_status[pending/success/failed], receive_status[pending/received], trade_no, paid_at, remark, created_at)`

平台服务费率默认 0.5%（`PLATFORM_SERVICE_FEE_RATE`），按订单金额计提，写入结算单 `fee_amount` 与 `settlement_line(biz_type=service_fee)`。

## 6. 溯源域

- `trace_batch(id, batch_no UK, qr_code UK, product_id, enterprise_id, origin_base, origin_region, plant_date, harvest_date, process_enterprise, process_date, warehouse_id, test_report_url, quality_status, status[active/closed], created_at)`
- `trace_event(id, batch_id FK, stage[planting/processing/warehouse/trade/sale], title, description, occurred_at, location, operator, evidence_url, created_at)`

公开扫码接口 `GET /api/v1/trace/public/{batch_no}` 返回产品信息、产地、企业、检测报告与链路事件（无需鉴权）。
