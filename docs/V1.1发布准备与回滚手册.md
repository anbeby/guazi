在业务服务器的独立发布目录中加载镜像、解压源码，并把 `.env.test.example` 复制为 `.env.test`。配置 `V11_DATABASE_URL` 时必须确认库名为 `gz_v11_release_check`；填入新生成的测试密钥，设置文件权限 600。测试上传目录 `/data/guazi/v11-test/files` 由 API UID 10001 写入。测试端口变量 `V11_WEB_PORT` 当前为 `18082`。

## 6. 故障回退原则

- 隔离测试故障：`docker-compose ... down` 仅停止 `guazi-v11-test`；保留演练库及 `/data/guazi/v11-test/files` 供排查。旧公网容器不受影响。
- 正式库迁移失败且没有新数据：保持旧应用停写，通过迁移日志确定版本；必要时在**新数据库**恢复备份、校验行数与健康检查后，再执行经过审核的切换。不要直接删除当前正式库。
- 正式版运行后回退：先导出升级后新增的线索与文件，再选择旧镜像和兼容数据库版本；数据回退步骤必须单独复核。不得把 `alembic downgrade` 当作无损恢复。
