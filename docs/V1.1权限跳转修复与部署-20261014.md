# V1.1 权限跳转修复与部署记录

时间：2026-10-14（北京时间）

## 问题与处理

普通注册用户登录后若携带 `/dashboard` 跳转参数，可能进入无权限后台页面；直接访问后台则被导向 `/404`，让用户误以为页面不存在。修复范围仅为前端路由与提示：登录后依据账号权限选择工作台或个人中心；无权限访问显示 `/403` 和个人中心入口。原有 `/404` 继续用于不存在的页面。

| 修改文件 | 修改原因 | 影响范围 | 验证结果 |
| --- | --- | --- | --- |
| `apps/admin-web/src/router/routes.ts` | 增加 `/403` 路由 | 管理前端路由 | 普通用户访问后台进入 `/403` |
| `apps/admin-web/src/router/index.ts` | 守卫等待用户权限加载，并校验登录跳转目标 | 登录后导航、后台权限跳转 | 普通用户进入 `/account`；管理员进入 `/dashboard` |
| `apps/admin-web/src/views/login/index.vue` | 登录提交时检查跳转目标权限 | 登录页 | 普通用户携带 `redirect=/dashboard` 登录后进入 `/account` |
| `apps/admin-web/src/views/error/404.vue` | 复用错误页呈现 403 说明及返回入口 | 403、404 页面 | 403/404 文案和入口分别正确 |
| `deploy/scripts/release-v11-guardfix-web.sh` | 固定单服务替换与回滚步骤 | 瓜子 admin-web 容器 | `guazi` Compose 项目下发布成功，健康检查通过 |

未修改数据库、API、业务模型、交易流程、端口、公网 Nginx、FRP 或其他平台容器。

## 发布后验证

通过 SSH 隧道在真实浏览器打开业务服务器现有 `127.0.0.1:18083` 入口：

| 场景 | 结果 |
| --- | --- |
| 普通用户通过 `/login?redirect=/dashboard` 登录 | 自动进入 `/account`，个人中心可见此前收藏 |
| 普通用户直接访问 `/dashboard` | 导向 `/403`，显示“当前账号没有访问权限” |
| `/403` 页面“前往个人中心” | 返回 `/account` |
| 管理员通过 `/login?redirect=/dashboard` 登录 | 正常进入 `/dashboard` |
| 不存在的地址 | 本地构建验收中继续进入 `/404` |

`gz-admin-web`、`gz-nginx`、`gz-api`、`gz-worker`、PostgreSQL、Redis、MinIO 等瓜子服务均为 healthy；`gz-frpc` 为 running，重启次数为 0；`18083` 的 `/ready`、`/`、`/login`、`/supply`、`/procurement`、`/403` 均返回 HTTP 200。增值运营平台 `18080` 容器仍 healthy，根路径返回正常登录跳转 HTTP 302。瓜子 web 与 Nginx 近五分钟日志未发现 error、fatal、panic 或 upstream 错误。

## 未解决的公网入口问题

从本机请求 `http://guazi.btszss.com/ready` 仍得到 `HTTP 403`，响应头 `Server: Beaver`。这与先前记录的云入口备案拦截现象一致；请求未到达瓜子应用。此问题不能用前端路由修复，公网可访问性仍需单独处理。此轮没有修改 DNS、证书、公网 Nginx 或 FRP 端口。
