## 六、下一步：让系统真正跑起来（4 条命令）

需要在**命令行可用的机器**上执行（当前开发机 shell 故障）：

```bash
# 1) 全栈启动（首次会构建 api 与 admin-web 镜像，约 5~15 分钟）
cd deploy
cp .env.example .env          # Windows: copy .env.example .env
docker compose up -d --build

# 2) 初始化业务数据（角色/权限/园区/企业/商品/库存/演示订单）
docker compose exec api python -m app.initial_data

# 3) 安装 Odoo 定制模块
docker compose exec odoo odoo -d gz_odoo -i gz_platform_base,gz_merchant,gz_product,gz_inventory,gz_trade --stop-after-init

# 4) 打印局域网访问地址
pwsh -File scripts/access-info.ps1       # 或 bash scripts/access-info.sh
```

验证清单：

```bash
docker compose ps                              # 12 个服务应全部 Up/healthy
docker compose exec api python -m pytest -q    # 约 45 个用例应全绿
curl http://localhost:8080/health
curl http://localhost:8080/ready               # database=up
```

## 七、必须坦白的验证状态与风险

### 7.1 为什么会卡住

本次开发全程处于**没有命令行**的环境：每一次 `pwsh` 调用都返回 `0xC0000142`（Windows DLL 初始化失败）。所以：

- ✅ 用文件工具完成了**全部编码与配置**
- ✅ 用静态核对（read/grep/glob）验证了跨文件一致性：接口路径、导入路径、权限码、字典键、服务名与卷名对应关系
- ❌ **无法执行**：`docker compose`、`pytest`、`npm install/build`、`git commit`、Odoo 模块安装

## 八、给决策人的三条建议

1. **先在一台 shell 正常的机器上跑通第六节 4 条命令**——这是把"代码完成"变成"可演示系统"的唯一剩余动作，预计 1 小时内可完成并暴露真实问题。
2. **优先修 Odoo 集成与前端构建**：这两项是风险最集中、也最容易出问题的地方；自研后端因为有测试覆盖，风险相对可控。
3. **第二阶段建议优先级**：园区费用与巡检 → 溯源二维码实码生成 → Superset 产业大屏 → 微信小程序端（第一阶段已预留全部数据模型与接口位）。
