# REST 接口规范（v1）

自研平台对外统一前缀 `/api/v1`，OpenAPI 文档：`/api/docs`，健康检查：`/health`、`/ready`。

## 1. 通用约定

### 1.1 响应信封

所有业务接口（除 `/health`、`/ready`、文件直出、`/trace/public/*` 的公开视图）返回统一信封：

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "request_id": "5f2a1c9e8b7d4a10"
}
```

- `code = 0` 表示成功；非 0 为业务错误码。
- HTTP 状态码同时表达传输语义：`200` 成功，`400` 参数错误，`401` 未认证/令牌失效，`403` 无权限，`404` 不存在，`409` 业务冲突（如库存不足），`422` 校验失败，`500` 服务器错误。
- 前端判定成功以 `code === 0` 为准。

### 1.2 错误码

| 错误码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000 | 参数或业务校验失败 |
| 40001 | 未认证 / 令牌失效 |
| 40003 | 无权限 |
| 40004 | 资源不存在 |
| 40009 | 业务冲突（重复编码、状态不允许、库存不足） |
| 40100 | 用户名或密码错误 |
| 40101 | 账号被禁用 |
| 40102 | 刷新令牌无效 |
| 50000 | 服务器内部错误 |

### 1.3 认证

- 登录后返回 `access_token`（默认 120 分钟）与 `refresh_token`（默认 7 天）。
- 请求头：`Authorization: Bearer <access_token>`。
- 退出登录后 `access_token` 写入 Redis 黑名单直至过期。
- 密码算法：PBKDF2-HMAC-SHA256，260000 轮，随机 16 字节盐。

### 1.4 分页与排序

请求：`page`（默认 1）、`page_size`（默认 20，上限 200）、`keyword`（模糊）、`order_by`（字段名，前缀 `-` 表示倒序）。

响应 `data`：

```json
{ "items": [], "total": 128, "page": 1, "page_size": 20 }
```

### 1.5 数据权限（企业隔离）

| 角色 | 可见数据范围 |
| --- | --- |
| platform_admin / finance | 全平台 |
| park_operator | 所辖园区内的企业、商品、库存、订单 |
| merchant / supplier / buyer | 仅本企业（作为买方或卖方）的数据 |

实现：`app/core/scope.py` 统一注入过滤条件，禁止在路由内手写隔离逻辑。

| GET/PUT | `/api/v1/contracts/{id}` | `trade:read` / `trade:write` | |
| POST | `/api/v1/contracts/{id}/sign` | `trade:write` | `{party: buyer\|supplier}` 双方签署后自动生效 |

**核心闭环（第一阶段验收主链路）**

```
采购商 创建询价单 → 提交
        ↓
供应商 在询价单下报价  (quotation)
        ↓
采购商 接受报价  →  系统生成订单(order + order_item, status=pending_confirm)
        ↓
供应商 确认订单  →  行锁扣减 inventory.quantity，写 stock_move(out)，
                    生成 transaction_flow(pending, direction=in)
        ↓
供应商 发货 → 采购商/供应商 完成  →  生成 settlement(应收) + settlement_line
        ↓
登记回款 payment  →  settle 状态更新，流水 pay_status=success
```

| GET | `/api/v1/portal/me/requirements` | 登录 | 当前企业的采购需求及审核状态 |
| GET / POST / PUT | `/api/v1/portal/me/enterprise` | 登录 | 查看企业认证状态 / 申请企业身份 / 维护企业资料 |
| POST | `/api/v1/portal/me/enterprise/image` | 登录 | 绑定本账号经 `/files/upload` 上传的企业展示图 `file_key` |
| GET | `/api/v1/portal/me/enterprise-leads` | 已认证企业 | 仅本企业被分配的咨询线索 |
| POST | `/api/v1/portal/me/enterprise-leads/{id}/response` | 已认证企业 | 记录本企业跟进反馈 |

线索状态：`new`（待处理）→ `following`（跟进中）→ `completed`（已完成）。游客线索不按手机号自动绑定后注册的账号；请保留线索编号，由运营人员查询。企业申请状态为 `pending/approved/rejected`；审核通过后才授予对应企业角色并可发布供需信息。
